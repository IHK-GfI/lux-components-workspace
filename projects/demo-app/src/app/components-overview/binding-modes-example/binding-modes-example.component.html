Bindungsarten der LUX-FormControls

Dieselbe <lux-input>- bzw. <lux-checkbox>-Komponente in vier Betriebsarten. Möglich wird das durch den FormValueControl- bzw. FormCheckboxControl-Vertrag aus @angular/forms/signals: Das value- bzw. checked-Model ist gleichzeitig das 2-Way-Binding und die Andockstelle für [formField].

1. Signal Form — [formField]

Der empfohlene Weg. Validierung, Fehlertexte, required und touched kommen aus dem Schema.

Erfolgreich abgesendet: {{ submitCount() }}×

{{ signalFormState() }}

2. Freistehend — [(value)]

Ohne jedes Formular. Das Model ist die einzige Quelle, es gibt keine Validierung.

Name: «{{ plainName() }}», Zugestimmt: {{ plainEula() }}

3. Klassische Reactive Forms — formControlName

Über die LuxControlValueAccessorDirective aus LUX_FORMS_COMPAT. Gedacht für bestehende Formulare — neue Formulare sollten Variante 1 nutzen.

Gültig: {{ reactiveForm.valid }}

4. Bisherige LUX-API — luxControlBinding

Unverändert lauffähig, damit bestehende Anwendungen nicht brechen. Als @deprecated markiert und mit der nächsten Major-Version entfallend.
